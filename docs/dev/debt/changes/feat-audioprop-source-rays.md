# libSceAudioPropagation

## change [libSceAudioPropagation](../../../core/libs/prx/libSceAudioPropagation/Export.cpp) lacks acoustic propagation

- [libSceAudioPropagation](../../../core/libs/prx/libSceAudioPropagation/Export.cpp) lacks acoustic propagation: attributes have no effect, sources expose 36 initially empty, invalid path slots and no ray geometry, rendering preserves the destination mix without adding path contributions, and allocated CPU work memory is mostly unused. Room, portal, source and material handles are tracked, but destruction after their system is destroyed silently succeeds without native lifetime semantics being confirmed. Occlusion, reflections and reverb are absent. The ray getters follow the module's in/out capacity and descriptor checks, but no direction is computed, and a calculated path set is always empty and invalid.

## add Silent stubs

- [sceAudioPropagationSystemGetRays and sceAudioPropagationSourceGetRays](../../../core/libs/prx/libSceAudioPropagation/Export.cpp) (libSceAudioPropagation) - the module at `0x47a0` and `0x3750` (module `047197064aa6ab20b27632fea16faf29a24e97f38d09dcbd7c15e6f47b0739a8`) reads the caller's count as a capacity and requires exactly `0x40` rays for a system and `6` for a source, then rejects any record whose descriptor is not `0x010107d7`/`0x58` with `0x8a700007`. It goes on to resolve each ray's hit against the rooms and materials; this host models no ray set, no source transform and no geometry, so the caller's records come back as they arrived and no hit is produced. A title that reads a direction from the buffer sees whatever it placed there.
- [sceAudioPropagationSourceCalculateAudioPaths](../../../core/libs/prx/libSceAudioPropagation/Export.cpp) (libSceAudioPropagation) - validates at the module's `0x56c0`: handle, pointers, `rayCount == 6`, non-zero reflection order and capacity, the six ray descriptors and the descriptor of every output slot, then writes `pointCount = 0` and `flags |= PathInvalid` into each requested slot, which is what the module writes for a slot it computes no path for. Nothing traces a ray, so no slot ever carries a path and a rendered source stays without path contributions.
- [sceAudioPropagationSourceSetAudioPaths](../../../core/libs/prx/libSceAudioPropagation/Export.cpp) (libSceAudioPropagation) - validates every `0x28`-byte entry of the module's `0x5280` path (`0x010107d9`, path handle at `+0x10`, path at `+0x18`, gain at `+0x20`) before changing a slot, requires a non-null entry array even with a zero count and rejects a zero count with `0x8a700001`, as the module does. The stored path is then the caller's data; nothing is traced for it, and a stored non-empty path still throws on render.

## add Functional

- [sceAudioPropagationSourceSetAudioPath](../../../core/libs/prx/libSceAudioPropagation/Export.cpp) (libSceAudioPropagation) - the module's single update at `0x50c0` rejects a gain that is not finite or lies outside `[0, 1]` (the constant at `0x1a8e0`) with `0x8a700001`, and its point loop only checks that each point position is finite. The host applies the same gain bound but throws `std::invalid_argument` instead of returning the code, and it also checks each point descriptor, the flags word and room ownership, which the module leaves to other code.
