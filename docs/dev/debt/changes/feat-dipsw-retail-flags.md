## change [sceKernelCheckDipsw, sceKernelInitializeDipsw, sceKernelIsAssistMode, sceKernelIsDevelopmentMode, sceKernelIsDisableRazor, sceKernelReadDipswData, sceKernelSetDipsw, sceKernelUnsetDipsw and sceKernelWriteDipswData]

- [sceKernelInitializeDipsw, sceKernelReadDipswData, sceKernelSetDipsw, sceKernelUnsetDipsw and sceKernelWriteDipswData](../../../core/libs/prx/libSceDipsw/Export.cpp) (libSceDipsw) - these still throw. Each opens `/dev/dipsw` and issues ioctls (`0x20008800` and `0x8010880a` with a 32-byte buffer in `sceKernelInitializeDipsw`, 0xd0, 232 bytes) and answers `sceKernelError(errno)` when the open or an ioctl fails, or 0 on success; the ioctl commands of Set, Unset and Read/Write were not decoded. AnyPS5 provides no `/dev/dipsw`, so the console's answer cannot be reproduced without inventing one. Their prototypes are still the parameterless import placeholders.

## add Unknown function info

- [sceKernelCheckDipsw and the four query wrappers](../../../core/libs/prx/libSceDipsw/Export.cpp) (libSceDipsw) - `sceKernelCheckDipsw(std::uint32_t id)` answers 0 for ids 0 to 255 and `sceKernelError(EINVAL)` (`0x80020016`) from 256 on, with the module's own bodies behind it: the 13.40 `libSceDipsw.sprx` (0x360, 318 bytes) compares the id's low 16 bits with 0x100 (`cmp $0x100,%bx; jb`, 0x37d) and rejects with `sceKernelError(22)` (0x391), opens `/dev/dipsw` with mode 2, fills a 32-byte table at 0xc020 through two ioctls, closes it and answers bit `id` of that table; when the open fails it still answers that bit from the same table, which is `.bss` and therefore zero (0x3f1 to 0x434). This host has no `/dev/dipsw`, so the table is zero and every query answers 0, which is also what a retail console answers because its table is zero; the divergence is the missing device, not the value. The four wrappers pass the ids the module passes: 0 for `sceKernelIsDevelopmentMode`, 2 for `sceKernelIsAssistMode`, 0x18 for `sceKernelIsDisableRazor` and 0x1e for `sceKernelGetDiableBinaryVersionCheckValue` (0x760 to 0x790, 7 to 10 bytes each). The module tests only the low 16 bits, so an id above 0xff whose low half is below 0x100 (0x10000, for example) indexes outside its 32-byte table; here it answers the error instead. Not measured on a console.
